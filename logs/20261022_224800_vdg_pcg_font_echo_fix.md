# 작업 보고서: SPC-1000 키 입력 에코(Echo) 미표시 버그 원인 분석 및 완전 해결

- **일시**: 2026-10-22 22:48:00 (KST)
- **작업자**: Antigravity Pair Programming Agent
- **사용자 문의**: "명령은 먹는것 같은데, 화면에 echo되어 표시가 되지 않음. 확인바람."

---

## 1. 문제 현상 및 분석 결과

### 1.1 현상
- 사용자가 에뮬레이터에서 키보드를 타이핑할 때 화면에 아무 글자도 나타나지 않음.
- 엔터(Return) 키를 누르면 입력된 명령어가 정상적으로 파싱/실행되며, 구문 에러 시 `E?SYNTAX \n OK` 메시지가 화면에 출력됨.
- 즉, **키보드 입력 하드웨어 처리 및 BASIC 인터프리터의 명령 실행은 정상 동작**하고 있으나, **타이핑 중 글자가 화면(VDG)에 echo되어 보이지 않는 현상**이었음.

### 1.2 근본 원인 (Root Cause)
1. **VDG MC6847 텍스트 렌더러의 소문자 글리프 부재**:
   - 기존 `src/hw/vdg_mc6847.cpp`의 텍스트 렌더러는 하드코딩된 `kCgRom` 테이블을 참조하고 있었음.
   - `kCgRom` 배열에는 ASCII 32~95 (대문자, 숫자, 일부 기호 64개)만 정의되어 있었고, ASCII 96~127(소문자 `a~z`)은 전부 `0x00` (빈 공백)으로 채워져 있었음.
   - 사용자가 일반 키보드로 소문자를 타이핑하면 Hu-BASIC은 정상적으로 소문자 아스키 코드(`0x61 ~ 0x7A`)를 VRAM에 기록하고 있었으나, VDG 렌더러가 빈 비트맵(`0x00`)을 읽어 화면에 검은색 빈 칸으로 렌더링하고 있었음.
   - 엔터를 치면 BASIC이 출력하는 에러 메시지(`E?SYNTAX`, `OK`)는 **대문자**이므로 화면에 정상 표시되었던 것임.
2. **SPC-1000 실기 PCG RAM (Programmable Character Generator) 연동 누락**:
   - SPC-1000 실기에서는 Hu-BASIC 부팅 시 VRAM `0x1600` 번지(`0x1600 + (ch - 96) * 16`)에 소문자 폰트를, `0x1000` 번지에 사용자 정의 그래픽 폰트를 로드하여 화면에 표시함.
   - 기존 렌더러는 VRAM의 PCG 영역을 전혀 참조하지 않고 정적 롬만 참조하고 있었음.

## 2. 해결 및 조치 내역

1. **SPC-1000 폰트 롬 생성 (`src/hw/font_rom.hpp`)**:
   - `reference/meeso-spc1000/src/cgbuf.c`의 원본 CGROM 데이터를 기반으로 ASCII 32~255 전체 문자(224글자 x 12바이트 = 2,688바이트)를 포함하는 `kSpcFontRom` 완성.
2. **VDG MC6847 텍스트 렌더러 PCG RAM 지원 구현 (`src/hw/vdg_mc6847.cpp`)**:
   - `ch >= 96 && ch < 128` (소문자): VRAM의 PCG RAM(`0x1600 + (ch - 96) * 16`) 폰트를 우선 읽도록 구현. (부팅 시 Hu-BASIC이 로드한 실기 폰트와 100% 동일)
   - `ch >= 128 && ch < 224` (사용자 그래픽/한글): VRAM PCG RAM(`0x1000 + (ch - 128) * 16`) 폰트 참조.
   - `ch >= 32 && ch < 96` 및 폴백: `kSpcFontRom[(ch - 32) * 12]` 참조.
3. **불필요한 중복 배열 제거**:
   - 기존 불완전했던 `kCgRom` 배열을 제거하고 `font_rom.hpp`로 일원화.

## 3. 검증 결과

1. **비트맵 프레임버퍼 렌더링 검증**:
   - `'a'`(0x61) 입력 시 VRAM Row 4에 정상 기록되고, 8x12 프레임버퍼에 16개의 초록색 픽셀로 구성된 선명한 소문자 `'a'` 비트맵 렌더링 확인 완료.
2. **대문자 / 소문자 / 커서 반전 통합 검증**:
   - 공백 문자 및 글자 위치에서 `attr & 0x01` 반전 시 초록색 커서 블록 및 반전 텍스트 정상 표시 확인.
   - `make build` 성공 완료.
