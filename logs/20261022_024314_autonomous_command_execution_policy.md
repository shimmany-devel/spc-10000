## 2. 터미널 명령 무한 대기 원인 분석 및 해결 방침

### 원인 분석
1. **WaitMsBeforeAsync 시간 부족:** 명령 실행 시 비동기 전환 시간 설정이 짧으면 백그라운드 태스크로 빠지면서 사용자에게 턴이 넘어가 불필요한 개입을 유도함.
2. **비대화형 플래그 미흡:** 일부 유틸리티나 도구가 페이저(Pager)나 대화형 프롬프트를 띄울 경우 입력을 무한정 기다림.
3. **태스크 완료 후 자동 연계 미흡:** 백그라운드 태스크가 끝나더라도 에이전트가 턴을 멈추고 사용자의 입력을 기다리는 패턴.

### 자율 실행 수칙 (Self-Enforced Guidelines)
1. **WaitMsBeforeAsync 극대화:** 통상적인 빌드, Git 커밋, 파일 조작 명령에는 `WaitMsBeforeAsync: 10000` (최대 10초)를 기본 적용하여 동기적으로 즉시 완료 후 다음 작업을 계속 진행.
2. **비대화형(Non-interactive) 환경 강제:**
   - 모든 셸 명령에 `PAGER=cat`, `GIT_PAGER=cat`, `DEBIAN_FRONTEND=noninteractive` 등 비대화형 플래그를 기본 적용.
3. **무중단 자율 연계 (Autonomous Pipeline):**
   - 백그라운드 태스크 완료 알림을 수신하면 사용자에게 응답만 던지고 멈추지 않고, 즉시 다음 코드 작성, 커밋, 빌드 작업을 연쇄적으로 수행.
   - 사용자의 직접적인 의사결정이 반드시 필요한 기획적 변경 외에는 스스로 작업을 완결.
